# 自动检测和报告采集

v1.15 将自检集成在原 App，无需电脑、root、公开 ADB 或 RustDesk 操作权限。适用于火锅实际使用的东北移动宽带 Wi-Fi；默认标签由用户明确选择，实际 Wi-Fi/流量/VPN 类型另行检测，标签不是运营商或位置的自动验证。

连接页点击“一键检测 · 自动提交报告”，保留当前网络，停止 RustDesk 屏幕共享，选择快速或详细检测。保持前台；离开前台会取消并保存已完成阶段。重新连接时原清晰度和码率偏好保留，候选推荐只有点击后才应用。

快速档：540P VBR 2.5、4、8 Mbps，720P VBR 4 Mbps，540P 自适应 VBR 4 Mbps，最后复测第一档；详细档将前五档正反顺序各测一次。每档五秒暖机，记录二十/三十秒，帧率目标三十、缓冲一百二十毫秒。估计快速三至四分钟，详细七至八分钟；超时会记录该档失败并继续。

服务端启动单独的 `local.remoteandroid.benchmark` 合成动画源，每次从同一固定周期开始。背景持续滚动，避免静止画面导致正常低帧率被误判为卡顿。检测使用同一套 H.264/AAC/控制通道，未另造模拟网络数据。源三十 FPS 只是调度目标，真实编码和手机表现由采样反映。

采集包括每秒接收/显示帧数、视频字节、RTT、App CPU、Java/原生堆内存、系统热状态、可用信号强度；阶段汇总包含停顿和最长间隔、丢弃过期显示帧数量、源/到达/显示间隔抖动、RTT P50/P95、实际解码器与硬件标记、系统声明的 H.264/H.265 硬解能力、电量及电池温度。缺失或系统不可读指标省略，不编造数值。

App CPU 百分比针对本进程，100% 相当于一个 CPU 核，可能超过 100%；堆内存不是整机占用；电池温度不是 CPU 温度，短测电量差不能解释为准确功耗。TCP 接收帧数与显示帧数之差不称为丢包率。

接收至渲染耗时按相同 PTS 匹配同一手机的两个单调时间戳计算，包含解码、等待和缓冲；PTS 仅作为匹配键，不用两台机器的时钟相减。它不是触控到画面变化的完整延时。RTT 仍为已有 TLS 连接上的 `/ping` 请求/响应耗时；显示回调不是光学测量，不能保证肉眼无撕裂。

自动建议仅比较至少两次有效采样，要求每次平均显示至少 25.5 FPS、最长停顿小于 500 ms、实际硬解、网络未切换、自适应未拒绝，且系统未达到严重热状态。优先选择较低分辨率、较低目标码率。条件不满足时保留原参数，不伪造“最佳”结论。快速档只重复基准，因此更多档位的自动比较应使用详细检测。

报告采用结构化 JSON（无画面/照片/密码/SSID/IMEI），通过既有账号和证书校验上传到当前填写的服务器。公网仍为用户的 NPS `146.56.249.175:15556`，没有新增服务端口。`POST /diagnostics/reports` 返回 `report_id`；同账号同报告编号和内容的重试幂等。`GET /diagnostics/reports` 与 `GET /diagnostics/reports/<UUID>` 都需要认证，且只读自己的报告。

M5 保存目录：`~/Library/Application Support/AndroidRemote/direct/diagnostics-reports/<账号SHA256>/<报告UUID>.json`。目录 700、文件 600；每账号 40 份、4 MiB、30 天。此目录不在下载页或 `/updates` 的匿名范围。维护者可以沿用已授权 SSH 读取。手机保留上次报告和回执，上传失败可重试。

检测场景接口仅启动/停止固定合成测试包，并使用账号、运行 UUID 和八分钟租约。停止只 force-stop 该测试包；如果停止请求未确认，UI 和报告标记清理未确认，租约保护尝试结束场景；网关异常退出或 ADB 失败时需维护者确认。它不接受任意 ADB 命令、包名或 Activity。
