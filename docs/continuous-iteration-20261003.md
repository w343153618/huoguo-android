# 连续迭代方式

2026-10-03用户要求：完成一轮实验或版本后直接继续下一轮，不等待再次确认，不再等待原来的四小时唤醒周期。

现有“安卓串流下一版优化”线程自动任务已通过工具改为每分钟续接检查，并从配置读回确认仍为ACTIVE、目标仍为本对话。正在执行的任务顺序完成代码、离线检查、可执行的真机实验、证据记录与实验分支推送后，继续下一项有证据支持的工作；一分钟计时用于中断后的续接，不是每分钟发布一个新版本或重复启动测试。只有有意义的新结果、失败、必须人工处理或阶段完成时通知。

每次续接先读取AGENTS.md、current-testbed和最新实验报告，核对已有候选端口、进程及冻结依赖，防止并发抢占同一手机或改正在实测的源码。正式会话在线时推进不打断连接的工作。设备不在线时做代码审查、fixture或分析；这些结果不能替代真机验收。机主独立实验与朋友正式部署的安全门槛仍分别保留。

本次立即开始的下一项是native接收诊断：独立拆分frame Mapping的旧frame、cap8及header mismatch拒绝，固定数值事件关联frame ID、准入和容量状态，保留原21项stats及所有接收策略。需要新JNI和APK的变化记录新SHA，不能追认到alpha3历史结果。随后在相同媒体行为和参数下做有界真实视频测试，再决定是否需要单因素队列候选。

本地自动任务需要Mac开机并保持Codex运行；若任务被应用关闭或设备断开中断，以最后一个工程checkpoint续接，不声称离线时仍在测试手机。
