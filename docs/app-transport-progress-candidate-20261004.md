# App receive-progress candidate following the public stall

The ordinary public M1 round reproduced a4.769s complete-frame/callback progress plateau and a5.031s observed SF gap. It did not retain per-interval ingress counters in the published App report. Kernel capture is currently unavailable: Mac BPF access was denied, and the phone's discovered tcpdump path could not be executed or read even under UID0. No global security settings were changed.

The next narrow source candidate reuses the existing RX-owned one-second `samples` collection in `UdpVideoProbe`. At that existing sampling point it adds cumulative UDP datagrams, authenticated-video datagrams, complete frames and codec callbacks. Existing authenticated-packet counts and native FEC snapshots remain. There is no new per-packet JSON, clock read, thread, live observer or queue modification. Existing sample collection is already present in alpha8; the new fields and final exporter are not present in that APK.

`numericTransportSamples` exports a closed, integral, monotonic column schema after the receive loop ends. It includes cumulative authentication/FEC expiry/reference/dependency/keyframe-request counts alongside frame/callback progress. The report retains at most64 initial samples out of the existing bounded3600-sample recording, explicitly reports the recorded/exported/omitted counts, and never claims whole-session observational coverage. Missing legacy samples/counters remain unavailable rather than becoming zero. No address, key, credential, decrypted body or arbitrary source JSON is exported. The existing64KiB whole-report rejection stays intact.

The sample time is `System.nanoTime()` at iteration start, before that iteration's socket receive and processing. Counter values can therefore describe work after the timestamp. It is not the exact last packet-arrival time. RX processing stalls can also create gaps in the sampler itself; continuing authenticated counters with stopped complete-frame counters supports reassembly/reference recovery, whereas stopped counters alone cannot prove physical network silence. A future matched helper can compare these phone-process clocks with its own progress samples; it must not directly subtract unrelated host or SF clocks. Acoustic/optical latency and actual packet routing remain unverified.

Root validation uses the actual extracted Java exporter and typed JSON substitutes on the JVM. Six focused cases cover authenticated progress with a complete-frame plateau, numeric FEC context,64-sample prefix retention, legacy/empty distinction, integral/monotonic/auth/FEC bounds, closed fields and reuse of the existing sample point. Related Inbox export and completion/report-rejection checks also run because the whole numeric report changed. These are source/JVM checks, not concurrent Android sampling-overhead or real-phone acceptance.

The candidate is not deployed or published. Preserve alpha8/code39 and its original signature/data until a new local build and matching helper pass the next owner-only real test. The previous local alpha9/code40 APK belongs to its earlier frozen source and cannot be credited with these fields. Existing public/LAN raw FIFO/session-FPS budget,80ms, codec/PCM switches and all M1/M5/NPS services remain unchanged.
