# M1 远程安卓的宿主与局域网隔离设计

日期：2026-10-02。范围：M1 上的 Android Emulator、其管理接口、串流服务与 guest 网络出口。本文记录当前只读审查和后续候选方案，**不是已部署的安全策略，也不是可直接加载的 PF 规则**。

用户要求：远程用户的能力限定在虚拟安卓内；不得读取或修改 M1 的无关资料，不得通过安卓攻击宿主、网关或其他局域网设备。用户允许 guest 保留 root，因此强制边界必须由 guest 之外实施。

用户明确：App 账号 `huoguo` 仅给火锅使用；App 账号 `wyw` 只供机主测试，不给他人使用。这两个是串流服务账号，不是运行身份隔离。M1 目前进程仍以个人 macOS 账号 `wyw` 运行；隔离 guest 出口与宿主文件访问的系统边界对两种 App 登录都适用，不因为机主测试登录就开放宿主 shell 或其他资料。

## 已部署的有限入口加固

2026-10-02 已补正式网关会话 owner 校验：其他账号不能凭 SID 接入视频、音频或控制，不能关闭或抢占不同账号的会话。正式更新下载只接受普通文件，使用末级 `O_NOFOLLOW`、非阻塞打开和大小限制，拒绝符号链接与 FIFO。相关离线范围检查共100项通过。两次本机已建立 TCP 连接检查均为空后，仅重载 M1 gateway；这不是原子会话锁。使用原证书 SHA 精确核对本机 TLS，`/ping`、正式清单正常，未认证 DELETE 返回401。既有账号、APK版本、AVD、NPC/NPS保持。

证据在 `evidence/m1-host-isolation-20261002/`，可复测工具为 `../scripts/security/audit_m1_isolation.py --owned-canaries`。跨账号真实凭据测试未执行，相关边界通过离线负向测试验证。以上只加固服务入口；**独立运行账号、文件沙箱、受限出口与重启后保护均尚未部署，不能据此宣称 Mac／LAN 已隔离。**

## 权限模型

至少分成两种非管理员运行身份，不复用个人 UID：

1. **Guest 运行身份**：运行 emulator 与必要子进程，拥有独立 AVD、缓存和日志；SDK 和可执行代码只读。不能读取网关认证资料、更新签名资料、个人 Home 或个人工程。没有 sudo、管理员组、远程登录、Full Disk Access、辅助功能、屏幕录制或个人 Keychain 授权。
2. **媒体／管理身份**：运行受限网关、编码器与必要的 ADB／gRPC 客户端，持有其专用状态和认证资料；只开放固定实例的媒体、原生触控及限定的 Android 媒体互传。不能获得个人文件访问权限，也不能向客户端提供任意命令、任意文件路径、任意转发目标或任意 ADB 指令。

可执行代码、账号启动配置、安全配置与策略文件由管理员持有，运行账号不能修改。AVD 状态与网关状态分目录、分权限；guest 运行身份不能读取网关账号摘要、证书私钥、NPC vkey 或更新密钥。现有受限凭据继续留在受限宿主位置，迁移时只复制该服务必需内容，不复制个人 `.ssh`、浏览器配置或整个 Home。

媒体 sender 与 guest 网络身份必须分开：guest 不得访问私网，而媒体 sender 必须能向已授权的 LAN／Tailnet 手机发包。若共用一个 UID，简单私网阻断会同时破坏合法串流；直接限制 `wyw` 还会影响用户正常使用 Mac。

## 文件与设备边界

独立标准账号只是第一层。其他账号仍可能读取 world-readable 文件，所以需要经过验证的宿主文件白名单，而不是只声称“账号不同就完全隔离”。

候选只允许读取所需 SDK、系统映像、动态库与系统资源；只允许写入该实例的 AVD、限定缓存、临时目录与轮转日志。明确排除个人 Documents、Desktop、Downloads、Photos、浏览器资料、SSH、个人 Keychain、其他工程和其他服务状态。

优先评估原生 macOS App Sandbox 或受限 launcher 的实际兼容性。第三方 emulator 的 Hypervisor、GPU、JIT、共享内存、gRPC 和子进程路径必须分别试验；不能把一份未测 `sandbox-exec`／Seatbelt profile 宣称为可支持的正式保护，也不能为让程序启动而宽泛放行整个个人 Home。只有在候选读取负向 canary 被拒绝、必要渲染编码路径正常、子进程继承边界得到核对后才考虑推广。

候选应关闭宿主麦克风输入、真实摄像头、宿主剪贴板同步、宿主共享文件夹和不必要的设备输入。保留安卓音频输出、通过 gRPC 获取安卓画面、原生安卓触控。文件互传只经过限定的 Android 媒体目录和专用临时缓存；无任意宿主拖放目录或远程自选宿主文件路径。核查 GPU 设备访问与相关 entitlements，避免授予不需要的设备能力。

应限制日志、上传暂存、AVD 磁盘增长和服务资源使用，防止 guest 或远程用户填满宿主磁盘、无限积累连接或耗尽队列。具体配额依据现有数据量和真实串流测试设置，本文不擅自改变磁盘或 CPU 配置。

## 网络边界与受限出口

保持隔离的用户态 NAT；不要为 guest 提供可信 LAN 的二层桥接。NAT 通常不允许 guest 直接在物理 LAN 发起 ARP 劫持，但会代发 TCP／UDP，仍然可能访问内网服务，必须另行约束。

guest 运行身份的出站默认拒绝，只允许经过审核的出口和模拟器内部必要通信：

- 拒绝宿主回环、宿主所有当前地址、LAN、RFC1918、CGNAT／Tailnet、链路本地、组播及管理地址；IPv4 和 IPv6 同时覆盖。
- 宿主地址集合必须随有线／Wi-Fi／IPv6 地址变化维护，不能只阻断一个历史 `.125` 或 `.128`。
- 正式 ADB、console、gRPC、SSH、Clash 控制 API 等不是 guest 可访问的普通出口。媒体身份访问固定管理端点和固定 guest 实例是独立例外。
- 需要公网 Web／DNS 时，经**受限出口组件**访问。guest 不能自行指定代理的任意 CONNECT 目标、内网目标或原始网络转发任务。

受限出口组件须在实际连接前校验解析后的目标地址，拒绝私网／回环／宿主地址；覆盖 A、AAAA、IPv4-mapped IPv6、重定向、重新解析与连接重试，避免只检查域名字符串导致 DNS rebinding 或 SSRF 绕过。每次新连接均遵守该约束，不能把首次检查通过当成后续所有解析均可信。出口代理自身也应有独立权限和目标过滤，不能访问个人文件或任意管理服务。

**不能给 guest 无限制地开放现有 Clash HTTP／SOCKS mixed port。** 否则 guest 可让 Clash 以另一个 UID 访问内网，从而绕过针对 guest UID 的目的地址限制。需要使用限制目标的专用出口；若它上游使用 Clash，也要在转交上游前完成目标约束，并验证上游不能把已批准的公网目标转换为内网路径。

Mac 到腾讯云 NPS／新媒体中继的连接继续采用现有国内物理出口，绕过境外代理，保留云端国内来源过滤。guest 的 YouTube 出口与媒体中继出口分别验证；不通过关闭全部 Clash／TUN 来掩盖路由问题，不修改云端来源过滤，也不重新引入旧 Headscale 域名。

## PF、沙箱与管理例外的能力局限

本机 `pf.conf` 手册说明：`user` 条件匹配本机 TCP／UDP socket 所有者；转发连接的 UID 为 unknown，其他协议不按 UID 过滤。有效 UID 在 socket 创建时记录；root 先创建 socket 再降权仍可能保持 root 归属。TUN、代理或系统网络扩展接管后，必须验证实际流量归属，不能假设规则依旧按 guest UID 生效。

`set skip on lo0` 会直接跳过回环过滤。若当前系统或其他软件存在该配置，必须先证明宿主别名访问仍被强制限制；不能在未评估其他软件的情况下全局替换 PF 主规则。采用独立 anchor，保留系统、Tailscale 和已有服务规则，记录启用引用及恢复过程。

模拟器内部存在 gRPC／netsimd 等回环通信。管理例外应逐项记录发起身份、目的端点、协议、认证方式与用途。不能为了兼容而放行全部 `127.0.0.1`、全部高端口或全部私网，也不能以“只监听 localhost”为保护证据。若某个内部端点因例外变得 guest 可达，需要验证认证与能力边界，或调整该端点架构。

本文故意不提供直接执行的 PF 成品规则：当前 PF 状态、TUN 路径、socket 归属、内部必要例外与 IPv6 行为尚未完成验收。系统策略安装需要管理员权限；管理员授权步骤不能被普通 App 的“最高权限”设置代替。

管理员现状读取已完成，PF enabled及根anchor结构已经读回；尚未做的是guest专用策略安装与实际隔离验收。`evidence/m1-host-isolation-20261002/sandbox-feasibility.json`记录独立合成子进程对自建文件读／写／创建、本机回环／LAN／IPv6 TCP的拒绝，以及单一允许localhost端口成功。数字IP SBPL语法首次失败后改为支持的localhost语法。该实验没有加载到VM，没有默认拒绝全资源策略或GPU／Hypervisor验收；`sandbox-exec`在本机手册标为deprecated，不可据此称正式沙箱完成。

## 生产迁移与回滚

1. 核对现有正式会话。有人使用时，不停止原实例、不切换账号、不替换规则；先完成离线源码审查、权限设计与候选构建。
2. 对既有 runtime／AVD／配置作可恢复备份。AVD 镜像应使用受支持的一致快照或安排受控停机后冷拷贝；不能把运行中直接复制 qcow2 的结果当成一致备份。
3. 创建独立候选目录和实例，保留原路径、原镜像、用户数据与原签名。候选初始保持 **6 核、16 GiB、1080×1920**，不把分辨率／编码参数变化混入安全迁移。独立 console、ADB、gRPC、网关与 UDP 端口需检查冲突后分配。
4. 先完成文件沙箱、设备输入、受限网络出口及管理接口负向验证，再做真实手机媒体与触控测试。负向验证不通过时不连接正式公网任务。
5. 记录候选代码版本、策略版本、身份、实际端口、镜像来源与回滚步骤。确认正式会话空闲后才切换正式服务；切换后重新核对云端来源地址与健康状态。
6. 保留旧 runtime、AVD 和启动定义用于回滚，不自动删除。回滚不得静默把不受隔离的旧实例重新暴露给远程用户；要明确保留的安全边界与服务可用性状态。

新账号、目录所有权、root 持有的启动定义、系统网络策略及可能的代码签名／沙箱配置，需要管理员安装过程。普通 `sudo -n` 无法完成；系统管理员认证读取已成功。实施时应准备一个具体、可审查的安装与回滚流程，复用已授权范围，处理系统必需认证，而不是反复要求用户批准每个普通测试动作。

## UDP 与安全的关系

宿主隔离与链路保护负责不同边界。实时媒体可以继续走 UDP，认证／完整性保护不要求把媒体变成 TCP，也不必制造可靠流的队头阻塞。当前认证 UDP 组件可保留会话密钥、AES-GCM 与防重放，再实际测量其 CPU／延时开销。

即使用户不要求画面保密，也不能把触控、控制或会话建立改成任意来源均可伪造的裸 UDP。攻击者不应能注入输入、重放操作或冒用主机。没有测试数据时，不宣称移除加密能显著改善 FPS。

账号、文件白名单、网络出口和 API 限制能显著缩小风险，但不应承诺未知 Hypervisor／GPU／emulator 漏洞“绝对零逃逸”。如果需要更强的物理边界，应使用不存个人资料的独立宿主与受限网络；当前 M1 方案以经过验证的多层限制为目标。
