# Protected source endpoints around a real phone window

The owner-only driver has a new, default-off `--source-stats-window on` option. It requires the existing numeric source guard, physical LAN, media-only sampling and the exact M1 guest. It does not acquire a lease: its coordinator must continuously retain the existing admission reservation and formal-session protection. The normal driver path, App defaults and deployed services are unchanged.

The candidate reads a fresh paused current-player Stats descriptor before instrumentation, explicitly resumes the same qualified source, then retains the existing playing-state and first-capture numeric guard. When both actual SF sampler processes finish successfully, it pauses the same source, reads a second paused descriptor and compares identity / VideoID / video and audio formats before publishing the helper's completion marker. The timestamps surround sampler dispatch and observed process completion; they are not exact SurfaceFlinger sample timestamps. Two equal endpoints do not prove uninterrupted content, motion, unique frames, decoding FPS, or optical / acoustic latency.

A separate `source_window_control.transition` routine uses a fixed MEDIA_PLAY or MEDIA_PAUSE, only after exact PID / cmdline / UID / start ticks, current foreground and active MediaSession reads. It checks the same bracket and requested state afterward. Already-paused cleanup sends no keyevent. It accepts only the M1 guest selector, never opens a menu, changes preferences, clears data or signals a service. The bracket is not an atomic Android input reservation; a device can change between reads. The external coordinator owns protection and must refuse active formal sessions.

The bounded control routine uses the existing reader with a six-second total budget, bounded output and local child reaping. The source XML remains in the collector's owned device temporary directory / ADB pipe and is never written to host evidence. Failure diagnostics export only declared labels and numeric evidence. Descriptor collection and the persistent Stats overlay have not had their overhead measured.

The installed alpha8 helper's steady marker deadline remains unchanged: steady duration plus two seconds, followed by a ten-second completion allowance. Slow endpoint collection can therefore reject the candidate. No timeout is silently extended. Failure cleanup requalifies the source before pausing, and the supervisor also pauses a source it attempted to resume before the long natural gateway shutdown.

Root verification: 62 focused inert checks passed, covering fixed-key controls, pre/post identity and foreground rejection, successful input without state change, no-input already-paused cleanup, driver opt-in boundaries, endpoint / pause / marker ordering, post-descriptor failure and mismatch refusal. This is source-level evidence, not phone playback or a new APK release.

The initial playing-Stats candidate was refused before instrumentation and media; its owned listener naturally exited and confirmed quiescence, with no signals. A separate protected source-only probe reproduced a three-second UI-command timeout while the exact active owner remained in playing state. Only the owned temporary-creation prefix arrived; fallback removal was confirmed, all local children were reaped, but remote UI completion was unconfirmed. A subsequent bounded process read found no matching UI / owned-temporary command. Source state was independently restored to paused. This explains the descriptor-acquisition failure of that candidate, not the streaming FPS problem. The new candidate moves both UI snapshots outside playback and does not extend the command timeout or install hooks.
