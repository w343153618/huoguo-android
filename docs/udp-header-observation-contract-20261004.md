# Bounded selected-peer UDP header observation

`scripts/probes/udp_header_observation.py` is a pure parser, not a capture launcher. It opens no files or sockets and does not operate devices. It accepts only classic PCAP2.4 with microsecond/nanosecond timestamps in either byte order, Ethernet (one VLAN optional) or raw IPv4 linktype101, and a64–160-byte snapshot. Unsupported formats, broken record extents or bounds fail with closed error codes. Header layout was checked against the installed primary libpcap `pcap-savefile(5)` documentation. This deliberately limited parser does not replace libpcap as a general capture reader.

Input is bounded to16MiB/100000 records/eight direction-and-envelope groups. Only the explicit server IPv4/high port and phone IPv4 pair is eligible. Fragmented IPv4, incomplete headers, inconsistent UDP lengths and invalid HGUE metadata remain separate counts. The expected encrypted-body snapshot truncation does not imply a malformed envelope. The parser reads only the24-byte prefix defined in `udp_probe_protocol.py`; no AES key or body interpretation is used.

Output excludes addresses, raw session tags, raw sequence numbers and bodies. It retains per-group relative duration, largest arrival gap, 100ms count bins, duplicates/reordering and unobserved sequence values within the captured span. These are unauthenticated capture observations. They do not prove packet loss, replay, video/audio lane identity, a domestic route, capture drop count, a complete window or physical latency. Audio and video share the server's envelope sequence space. A tag only separates opaque groups; it is not authenticated ownership evidence. Regressing capture timestamps and bins outside bounded retention are explicit, not silently repaired.

Root verification:16 focused fixtures passed, covering both precisions and byte orders, a five-second arrival gap, truncated body versus incomplete header, exact peer filtering, VLAN/options/raw IPv4, fragment refusal, malformed record sizes, group/record/bin bounds, duplicate/reordered sequences and capture timestamp regression. This verifies parser semantics only, not concurrent capture overhead or any phone performance result.
