# 真我 V50 的远程安卓均衡预设

调查日期：2026-09-29。目标设备是用户朋友火锅使用的 **realme 真我 V50**，不是 vivo V50、realme V5，也不直接用 V50s、Narzo 60x 等机型的测试结果替代。

## 建议

推荐把“一键优化”实现为**可查看、可手动改回的客户端预设**，不要把它描述成刷机、超频或系统清理。它不需要手机 root。推荐初始值如下，属于针对当前链路的工程选择，还没有火锅真机持续播放的测量数据。

| 参数 | 初始设置 | 依据和限制 |
| --- | --- | --- |
| 竖屏串流尺寸 | 540 × 1200，540P 档 | 每帧 64.8 万像素，是 720 × 1600 的 56.25%、1080 × 2400 的 25%；优先减少编码、解码和传输量。像素比例不等于功耗按同比例下降。 |
| 视频编码 | H.264 / AVC | 当前客户端和已验证服务端链路均使用 AVC；不因为一份手机规格就自动切换 HEVC。 |
| 手机解码 | 优先硬件解码 | 使用本机 MediaCodec 声明和实际解码是否成功来选择，无法仅凭手机名保证。 |
| 目标帧率 | 默认最大 30 FPS，可手动选择60 FPS | 在没有火锅真机持续播放数据前，降低解码与显示频率，优先稳定与持续使用。它是上限，不会把 30 FPS 视频自动补成真正的 60 FPS，也不能保证源端或公网始终达到 60。 |
| 视频目标码率 | 2.5 Mbps，VBR | v1.12 根据用户同一公网地址的 WiFi/电信流量对比（VBR更顺畅）调整预设。不是独立受控测量，不保证所有运营商上都更快；仍可手动选择 CBR。 |
| 播放缓冲 | 120 ms | 相比原有约 80 ms 略多留出网络抖动余量；以增加少量反馈延时换取更均匀的显示，不补出缺失帧。 |
| 显示刷新 | 请求 60 Hz / 60 FPS 匹配 | 系统可能忽略请求或选择 120 Hz 等整数倍；不可声称已强制锁定 60 Hz。 |
| 客户端声音 | V50预设默认1.5倍，可选原声/2倍/3倍 | 当前用户报告声音偏小；解码后PCM16轻度放大并软限幅。没有真机响度计测量，仍需听感验证。 |
| 检测指标 | 默认隐藏，可一键恢复 | 减少遮挡；这不是大幅降低耗电的主要措施。 |

以上数值是**平衡起点**，不是已测得的最佳值。v1.13 新安装默认采用V50均衡预设；升级保留已有设置，点“一键优化”应用。系统声明60FPS不再自动启用60FPS。

视频码率 2.5 Mbps 理论上约 1.125 GB/小时，不包含音频、TLS 和其他协议开销。家中源端与 NPS 的 200 Mbps 中转能力不意味着需要给这台手机更高码率。

## 官方资料能够确认什么

真我官方[寄修服务产品列表](https://www.realme.com/cn/support/repair-personal)明确列出真我 V50 和 V50s。调查时真我 V50 的[产品页](https://www.realme.com/realme-v50)及[规格页](https://www.realme.com/realme-v50/specs)不可读取，不能将未读到的规格当作已验证事实。

[MediaTek 天玑 6100+ 官方规格](https://www.mediatek.com/products/smartphones/mediatek-dimensity-6100plus)列出两颗 Cortex-A76、六颗 Cortex-A55、Mali-G57 MC2、6 nm 及最高 120 Hz 显示支持，但**该页没有列出 H.264/H.265 视频硬件解码规格**。它也不能单独证明火锅手机的实际硬解表现。不能用其他 MediaTek 芯片的 HEVC 白皮书替代 6100+ 的证据。

真我[官方安全维护页面](https://www.realme.com/security)还将 RMX3783 列在 Narzo 60x 5G 下，因此不能只凭 RMX 型号做绝对的市场机型映射。按钮可以允许用户主动选择“真我 V50 均衡优化”，实际能力检查则以正在运行的手机为准。

Android 的[媒体格式表](https://developer.android.com/media/platform/supported-formats)列出 AVC 解码和 Android 5.0 起的 HEVC 解码支持。这是平台格式支持说明，**不能据此认定真我 V50 一定能以硬件解码当前分辨率和帧率的 HEVC 串流**，也不能得出它只能解码 H.264。

## 一键优化应配合本机能力检查

客户端可以分别检查 `video/avc` 和 `video/hevc`：

1. 枚举非编码器、非别名的 MediaCodec，读取硬件/软件标志及名字。
2. 查询 540 × 1200 或服务端实际对齐后的尺寸是否支持，以及 `areSizeAndRateSupported(width, height, 60)`。
3. 对 AVC 优先选择合适的硬件解码器，实际创建、配置和播放成功后再显示“正在使用硬件解码”。默认保留30FPS，即使声明支持60FPS也不自动提高；若没有AVC硬解则预设降至432P/1.5Mbps。
4. 对 HEVC 只报告本机所声明的能力；当前 AVC 链路没有 HEVC 码流协商和接收实现时，不提供看似可用的 H.265 切换开关。

[`isHardwareAccelerated()` 官方文档](https://developer.android.com/reference/android/media/MediaCodecInfo#isHardwareAccelerated())说明这个属性由设备厂商提供，不保证其声明绝对正确。[VideoCapabilities 文档](https://developer.android.com/reference/android/media/MediaCodecInfo.VideoCapabilities#areSizeAndRateSupported(int,int,double))提供尺寸/帧率检查；可达帧率数据也可能缺失，不能当作持续播放实测。

[Android 帧率 API 文档](https://developer.android.com/media/optimize/performance/frame-rate)说明刷新请求由系统综合决定，不保证应用得到请求的刷新率；需要按每帧时间戳均匀提交画面。不要每帧反复请求刷新率。

## 真机验证与后续调整

让火锅更新后先使用这个预设，连续刷短视频 15 分钟，分别比较同一 Wi-Fi 和外网：检查实际解码器、显示 FPS、连续滑动是否断续、音画同步、发热和耗电。没有温度/功耗实测前，不承诺具体电池时长或降温幅度。

若 540P 仍持续掉帧，先区分源端编码不足、网络丢包/重传、手机解码或热降频；不要只增加码率。网络差时可试 432P 和更低码率；默认30FPS会降低滑动的时间细腻度；实际V50持续播放稳定、温度和电量表现可接受后，可以手动试60FPS。真机播放稳定并且文字清晰度不够时，再试 720P / 4 Mbps，保留随时回到均衡预设的入口。
